## 1. Context

`agent-memory` stores PII-equivalent free text in `Memory.content`/`Memory.statement` (BRIEF Constraints Regulatory) with Concept derived tokens ≤8, purpose `segundo cerebro`, governed by single-tenant local consent. Its Ley 172-13 posture was declared in `docs/CONTRACT.md` v1.4 (Concept-retention: purpose+TTL+deletion, two-half deletion `forget`/`delete`/`purge` + operator orphan cleanup, honest right-to-erasure boundary) and `ARCHITECTURE.md` NFR Security (`BRAINY_TTL_DAYS` 365 default, `purge`/`forgetNote`, mask/tokenize).

Brainy widens the PII surface: new primary store `Note.content` (`title 1..500`, `content 1..200k`, `tags string[64] 1..200`, `embedding Vector<1536>`) plus compat `Memory.statement`, both carrying the same free-text risk, plus automated inference (classifier PARA embeddings `>0.85 RELATES_TO`, 1536-dim remote provider `text-embedding-3-small`) and cross-agent exposure (MCP `brainy_search`/`brainy_capture`/`brainy_link`/`brainy_reality_check` consumed by Claude/Cursor/Gemini). Every new `port` (REST `/v1/notes|search|context|link`), `adapter` (HelixStore `saveNote`), `event` (hooks `capture.mjs` 7 events), `log` (access/governance/MCP stderr), `prompt` (`reality_check`), and `export` (`brainy export --format markdown` Obsidian vault) is a PII checkpoint under Ley 172-13 and the frame-ship Shared Foundation (Ley 172-13 cross-cutting): minimization, purpose limitation, store declares `purpose+TTL+deletion` with automated enforcement, data subject rights ARCO, cross-border only to adequate jurisdictions, DPIA for high-risk, privacy by design/default, breach notification 72h, no secrets/PII in logs/exports/evidence.

This SPEC (R4, complement to SPEC-001 R1 + SPEC-004 R2) freezes the legal declarations, TTL/deletion procedures, ARCO flows, cross-border rule, DPIA trigger, privacy-by-design checkpoints, and breach notification — with testable AC and allowlisted evidence only (no raw PII, no secrets). No freelance fixes: Critical/High surface same-session with severity+evidence+owner `subero`/`barrera`. Cross-domain triggers: new PII store/export/cross-border → `subero` review + DPIA if high-risk; new boundary/dependency/secret handling → `barrera` before merge; pipeline gate weakening → security+platform approval.

### Functional — TTL, Deletion & Orphan Cleanup

- **REQ-BRAINY-LEG-03 — TTL `BRAINY_TTL_DAYS` 365 default + deletion `purge`/`forgetNote`/`delete` + orphan Concept cleanup with automated enforcement (BRIEF Constraints + ARCH NFR Security + CONTRACT v1.4 two-half, maps to NFR-BRAINY-ENG-04):** Declare and enforce: **TTL** `BRAINY_TTL_DAYS` default `365` (canonical `BRAINY_*`, alias `AGENT_MEMORY_TTL_DAYS` 1 versión with single `WARN deprecated use BRAINY_TTL_DAYS` on stderr per ARCH §3; absent/invalid/≤0 → TTL OFF is declared and fail-closed, not silent). `Note.status`/`Archive.archived_at` inherit project TTL (BRIEF Open Question #4 resolved: `BRAINY_TTL_DAYS` is the single default; per-PARA TTL is a separate proposal, not implicit). **Deletion procedure** two halves: (a) Per-note/memory `forgetNote` (`forgetMemory` compat) / `POST /v1/notes/:id` delete alias / `POST /memory/forget` / `POST /memory/delete {memoryId,reason}` governance log allowlist + `scripts/purge.ts` (Helix-direct, `--days N` `≥1` + ` --project P | --all`, `--dry-run`, batches 500 `listExpired` `$id Asc`, `forgetMemory` per id, allowlist output `purge project=<p|all> days=<n> deleted=<m> at=<iso>` with `status=partial` on failed run, CWE-117 `oneLine` collapsed, never content) + `DELETE /memory/todos/:id` / `purge` for Note/Archive. (b) **Orphan Concept cleanup** operator-run manual (no scheduler in Brainy v1, declared as such): `Concept {name,project}` remains shared search vocabulary (TTL none intentional per CONTRACT v1.4: global uniqueness `nodeUniqueEquality("Concept","name")`, cardinality-bounded, per-memory drop not implemented because other memories/projects may reference the name). After (a), orphans = `Concept` with zero incoming `HAS_CONCEPT` edges globally — 3-step procedure verified live: audit `helix query dev -e 'readBatch().varAs("all", g().nWithLabel("Concept")...).varAs("linked", g().nWithLabel("Memory").out("HAS_CONCEPT").dedup()...).returning(["all","linked"])'` → client-side set difference; per-target zero-edge gate `in_edges==0 && in_edges_labeled==0 && out_edges==0` → `writeBatch().varAs("dropped", g().nWithLabel("Concept").has("name","<name>").drop())` → re-audit counts `−1` with `linked` unchanged. **Automated enforcement:** `BRAINY_TTL_DAYS` filter (`filterExpired` before return + `signals: ["ttl: hidden N expired rows"]` when N>0) + `purge.ts` is the only bulk TTL path; no multi-drop, no silent thinning. Owner `subero` (legal) + `vasquez` (engineering enforcement) + `espinoza` (ops `BRAINY_DATA_DIR` note: TTL is logical ageDays, not filesystem). Evidence: `src/search.ts filterExpired` + `scripts/purge.ts` allowlist output + live orphan audit before/after + `ARCHITECTURE.md` NFR Security + `docs/CONTRACT.md` v1.4.

### Functional — Data Subject Rights ARCO (Access / Rectification / Erasure / Objection)

- **REQ-BRAINY-LEG-04 — ARCO rights within legal timeframe via `forget`/`delete`/`search`/`update` (Ley 172-13, BRIEF Constraints, Shared Foundation):** Data subject rights are honored through existing store operations with response within Ley 172-13 legal timeframe (acknowledge ≤5 business days, resolve ≤15 business days; contractual SLA for Brainy single-tenant local — owner `subero` tracks; delay beyond triggers escalation to orchestrator). **Access:** `POST /v1/search` / `GET /v1/context/:project` / `GET /v1/notes/:id` / `listNotes` / `POST /memory/search|smart-search` / `GET /memory/sessions/:sessionId/memories` return caller's scoped data by `project` tenant (never cross-project). **Rectification:** `updateMemoryContent` (compat) / `moveNote` (para correction) / `distillNote` + `SUPERSEDES` lineage + re-embed `setProperty` path (probe4 verdict A: `setProperty` refreshes vector+text indexes; `embeddingsEqual` 1e-6 f32 guard). **Erasure:** `forgetNote`/`forgetMemory` hard-delete Memory/Note + incident edges (`BELONGS_TO`/`HAS_CONCEPT`/`RELATES_TO`/`REFERENCES`/`SUPERSEDES`) per CONTRACT §2; `POST /memory/delete {memoryId,reason}` with governance log `memoryId`+`reason`+`at` (receipt `{memoryId,deletedAt}` omits `reason` by design, reason lives only in governance line); `purge --days` bulk erasure; `DELETE /memory/todos/:id` for Todo. After erasure, orphans become eligible for (b) above — honest boundary declared: a `Concept.name` still referenced by other memories/projects cannot be dropped without breaking those rows (accepted, derived tokens non-PII W-3). **Objection / restriction:** caller may omit caller-supplied `concepts`/`tags` or set `project` isolation to restrict capture, and contest automated PARA classification (`RELATES_TO >0.85`) via `brainy move` / `moveNote` (`AGENT_MEMORY_CAPTURE_PATHS=basename` opt-in stays OFF by default). (Accepted drift fixed per CDR-04 with orchestrator + `ACK-R1-CDR-04`, commit `e1c541a`: no `AGENT_MEMORY_CAPTURE` kill-switch exists in code — 0 hits outside `CAPTURE_PATHS`.) All ARCO flows use bearer `BRAINY_SECRET` alias `AGENT_MEMORY_SECRET`; no auth bypass. Every checkpoint response masks `Note.content` with allowlist (`id`/`score`/`graph_path`/`project`, never raw secret) except explicit access flows which return content to the authenticated owner only. Evidence: `src/server.ts` + `src/store.ts` + `db/queries.ts` `forgetNote`/`forgetMemory` + `src/mcp.ts` `brainy_*` + governance log fixture (redacted).

### Functional — Cross-Border Transfers

- **REQ-BRAINY-LEG-05 — Cross-border transfers only to approved jurisdictions with adequate protection (Ley 172-13, Shared Foundation):** Cross-border transfer of `Note.content`/`Memory.statement`/embeddings is FORBIDDEN by default (single-tenant local; HelixDB `storage=disk` MinIO/S3 is the declared store; `helix.toml [local.dev] storage=disk`, `BRAINY_DATA_DIR` under `$HOME`/`/tmp`). Transfer to a third country / external LLM provider (`BRAINY_LLM_PROVIDER` `openai|gemini|anthropic` for `brainy distill`, remote `text-embedding-3-small` via Helix providers) is allowed ONLY if: (a) destination is on the **approved jurisdictions** allowlist with adequate protection per Ley 172-13 (list maintained by `subero`, versioned in this SPEC §4.4 and `SECURITY_REVIEW.md`), (b) DPIA for that transfer is PASS (REQ-06), (c) explicit consent or contractual necessity is recorded, and (d) data is minimized (only the summarized `Note.content` slice or `content 1..200k` needed for the provider, never full vault). Any new export, S3 bucket region outside approved set, or MCP cross-host relay that would move `Note.content` cross-border requires prior `subero` written approval + remediation plan with deadline; residual risk explicit, no silent PASS. The `brainy export --format markdown` local vault write is NOT a cross-border transfer; pushing that vault to a remote git/S3 is operator-responsible and must carry the same approval gate. Evidence: `SECURITY_REVIEW.md` cross-border table + this SPEC §4.4 allowlist + `ARCHITECTURE.md` Data Flow 3 (distill) + `helix.toml`.

### Functional — DPIA High-Risk

- **REQ-BRAINY-LEG-06 — DPIA for high-risk processing before go-live (Ley 172-13 DPIA, Shared Foundation, Cross-Domain Interface Engineering↔Legal/Privacy):** A DPIA (Data Protection Impact Assessment) is **mandatory before merge** for any high-risk processing introduced or widened by Brainy, and must be recorded with `subero` + `barrera` sign-off. Triggers (non-exhaustive, any triggers → DPIA): (a) **Automated classifier embeddings** — `saveNote` embedding `1536` + PARA auto-classification + `RELATES_TO auto>0.85` + `graphSearchNotes(max_depth)` (inference about interests, projects, resources; probes re-identified preferences e.g. `TypeScript estricto/pnpm`); (b) **MCP cross-agent sharing** — `brainy_search/capture/link/reality_check` + compat `memory_*` exposed via stdio to Claude/Cursor/Gemini CLI (cross-agent PII sharing boundary, `_meta.authorization` is the only gate, `tools/list` is pre-auth discovery — residual declared in SPEC-004 §4.2); (c) **Vector indexes with tenant `project` but global `Concept.name` uniqueness** (re-identification via shared vocabulary); (d) **Bulk export / `GET /v1/context/:project` graph traversal** (over-share `graph_path`). DPIA scope: purpose, necessity/proportionality, risks to data subjects (S/T/R/I/D/E per SPEC-004 §4.1), controls (see §4.3 checkpoints), residual risk with owner+expiry, and mitigation (minimization, allowlist logs, scoped search `where project` before `vectorSearchWith`/`textSearchWith`, bearer fail-closed, TTL, erasure). The Brainy v1 DPIA baseline (this SPEC + SPEC-004) is the first DPIA artifact for the new stores; each later high-risk change amends it rather than duplicating. Evidence: `DPIA-BRAINY.md` (or `SECURITY_REVIEW.md` DPIA §) + `subero`/`barrera` sign-off + `ARCHITECTURE.md` NFR Security reference.

- **REQ-BRAINY-LEG-07 — Privacy by design and default — minimization, purpose limitation, allowlist at every PII checkpoint (Ley 172-13, Shared Foundation):** Privacy is the default state: the system collects ONLY what the purpose needs and exposes PII only where explicitly requested by an authenticated caller.
