Bearer coverage unchanged: the 3 commits produce an empty diff on `src/server.ts`, `src/auth.ts`, `src/mcp.ts`, `src/errors.ts`; the guard still runs before route dispatch (`src/server.ts:238`), `livez` alone exempt; route table unchanged (`src/server.ts:245-402`). 2. **Project scoping as authorization boundary — fail-closed CONFIRMED.** All three new queries carry `Predicate.eqParam("memoryId") AND Predicate.eqParam("project")` in ONE where-clause (`db/queries.ts:548-549`, `585-586`, `625-626` — read, read-links, write-anchor). Because `memoryId` never comes from the request on this path, cross-project access additionally requires knowing a foreign UUID; and `project` is namespace hygiene inside a single shared-bearer trust zone, not per-user AuthZ (single-tenant tool, contract §Auth). One pre-existing asymmetry recorded as SEC-F03 (out of this diff).
3. **Error-message hygiene — 500 bodies CONFIRMED detail-free.** REST: `sendJson(res, 500, { error: "internal_error" })` (`src/server.ts:440`); MCP: `failed({ error: "internal_error" })` (`src/mcp.ts:145`). No embedding vector, no content body, and no secret ever enters a throw message (verified across all new `throw new Error(...)` sites in `src/store.ts:858-1030`).
4. **Secrets — none.** Regex sweep (`sk-…`, `BEGIN.*PRIVATE`, `password=`) over `db/queries.ts`, `src/store.ts`, `src/consolidate.ts`, `scripts/verify.ts`, `scripts/verify-lifecycle.ts` → empty. `AGENT_MEMORY_SECRET` referenced only as `process.env` read (`scripts/verify.ts:35`) and docs prose. Embedder is keyless by design (`src/embed.ts:1-13`).
5. **DoS amplification — assessed, Medium, non-blocking → SEC-F01.** Worst-case Helix round-trips under BOTH nested locks (dedupKey OUTER → survivor INNER): fresh read 1 + write 1 + verify-before 2 + heal 3 + verify-after 2 = **9 sends**, each capped at 15 s (`src/store.ts:50`, `src/store.ts:477-478`) → theoretical lock hold ≈135 s per merge. `withFifoLock` (`src/store.ts:509-526`) has no queue cap and no waiter deadline; the HTTP server sets no request/socket deadline (no `server.timeout`/`headersTimeout` in `src/server.ts`). Abuse shape: a burst of DISTINCT near-dups all picking one survivor serializes 1 client req → ≤9 Helix queries (write amplification), waiters accumulate unbounded (each retaining a ≤1 MiB body, `src/server.ts:32`, content ≤200 KB, `src/server.ts:37`) → latency + memory amplification. Mitigations that keep this Medium not High: localhost single-writer contract scope, body/content caps, per-query 15 s timeout, optional bearer, embedder is in-process FNV (zero network). From the abuse angle this is the SAME issue the resilience lane already flagged as unbounded queue wait — my opinion: track it there as one item (queue cap + request deadline), owner engineering; it is not a security blocker for this lane's scope.
6. **Prototype-pollution / injection via concept names — no new exposure.** The heal builds `missing.map((name): … => ({ name }))` (`src/store.ts:976-978`) — fresh object literals with a single fixed key, never a spread of caller objects; `missingConcepts` is pure string set math (`src/consolidate.ts:94-104`). Names still flow through the SAME `conceptBody()` parameterized upsert (`db/queries.ts:189-216`, `PropertyInput.param`) used by `saveMemory`/`updateMemoryContent`, and REST/MCP validate them first (`src/server.ts:42`, `src/mcp.ts:33`: ≤64 × ≤200 chars, trimmed). Concept-anchor-by-name-only cross-project linkage is a pre-existing property of `conceptBody` (SEC-F04); reads stay project-filtered (`db/queries.ts:379-380`), so the heal adds no disclosure path.

8. **Privacy / Ley 172-13 — CONFIRMED in-process.** `verifyMergedState`/`getFreshSurvivor` read `content` inside the store and compare bytes; nothing logs it (only `typeof` in a throw, `src/store.ts:881-884`). `fSurvivorContent` in `scripts/verify.ts` reads survivor content but asserts via `contentLen` only. ## Verdict Rationale

STRIDE mapping for the delta: **Spoofing** — auth surface byte-identical (empty diff on server/auth/mcp/errors; guard still pre-dispatch, `src/server.ts:238`). **Tampering** — the lane's whole point: fresh re-read under lock + post-write verify + link-only heal that structurally cannot write content/embedding/dedupKey (`db/queries.ts` heal batch touches only Concept upsert + edge); all three new queries fail closed on id/project mismatch. **Repudiation** — access log metadata-only (`src/server.ts:413`), unchanged. **Information disclosure** — 500/MCP errors detail-free; no content/embedding/secret in any new throw or log; only bounded concept-name fragments on the rare failure path (SEC-F02, Low). **Denial of service** — real amplification delta (SEC-F01, Medium) but capped by body/content limits, 15 s per-query timeout, in-process keyless embedder, and single-writer localhost scope; explicitly the same item resilience already tracks — non-blocking. **Elevation of privilege** — no new routes/tools/params; project+memoryId double where-clause on every new query; heal cannot escalate beyond what `saveMemory` already allowed under the same bearer.

No Critical or High findings. The one Medium is an availability/abuse-shape item that (a) predates this lane in essence (unbounded queue wait was already flagged by resilience), (b) is bounded by existing caps and timeouts, and (c) is explicitly scoped out by the contract's single-writer localhost assumption until P4.3.
