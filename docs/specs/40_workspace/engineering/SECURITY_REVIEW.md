## Threat Model

### Attack Surface

| Surface | Entry Point | Trust Boundary |
|---------|-------------|----------------|
| `agent-memory start/stop/status/doctor [--slot N] [--data-dir PATH] [--migrate --apply --yes --backup-dir PATH]` | CLI invoked by the operator (argv + env) | internal (local machine) — argv is operator-trusted, **flag/path values are still validated fail-closed** |
| State file `<parent-of-data-dir>/state/slot-<N>.json` | Read by `stop`/`status`/`doctor`; written by `start`; described as "sole authority any signal path may consult" (`ARCHITECTURE.md:34`) | **semi-trusted** — on-disk file, forgeable by any process running as the operator (or any writer to `~/.local/share/agent-memory/`) |
| Child processes: `helix start/stop/restart`, `helix add local`, `npx tsx src/server.ts` | spawned with inherited env | PATH-resolved executables → **PATH is a trust input** (S-011) |
| HTTP probes: slot `HELIX_URL /healthz`, slot REST `/memory/livez`, `/memory/health` (+ `Authorization: Bearer <secret>` in `doctor` C2) | whatever process currently holds `127.0.0.1:R(N)` / `H(N)` | **the listener is not authenticated before the bearer is sent** (S-001) |
| Migration artifacts: source MinIO volume (read-only), `<target>.backup-<UTC-ts>` archive, target `HELIX_DATA_DIR` | filesystem, possibly bind-mounted into a uid-`65532` container | new **at-rest PII store** (S-002) |
| Output channel: `doctor`/`status`/`--migrate` stdout+stderr | §4b allowlist renderer | Ley 172-13 boundary — child-process text and raw `Error.message` are outside the allowlist unless re-rendered (S-007, S-013) |

### Residual Risk (accepted, owner stated)

1. **PID-reuse TOCTOU between check and SIGTERM** (`PROPOSED_CHANGES.md` R-011, `RUNBOOK:393-395`) — narrowed by cmdline re-verification, milliseconds window, freshly spawned children. **Accepted as Low, owner R1**, *provided* C10 (re-verify before SIGKILL) is implemented — without C10 the window spans the whole grace period, which is not the accepted residual.
2. **Local same-user threat model** — an attacker who already runs as the operator can read the operator's env directly; findings here defend *intra-user tamper-resistance* (forged state, PATH, spoofed listeners) and *cross-user* disclosure (ports on `127.0.0.1`, `0644` archives). Blast radius stays local: no customer data, no multi-tenant surface, no external send (`PROPOSED_CHANGES.md:93`).
3. **A3 probe not yet run** (`HELIX_DATA_DIR` honoring + uid-65532 permission mode) — declared falsifiable at execute-spec step 0; fail-closed abort is the mitigation, framing 3b the fallback. Security posture does not change under 3b (less data moved, never more).

## Directed checks (packet checklist)

**(1) Does any spec'd code path print a secret?** — **No, by design; one ordering gap makes it reachable anyway.** Every spec'd render site is flag-only: `bearer: armed|unset` (`REQ-04`), `secret: present|missing` (`C4`, `RUN-REQ-01`), `auth: open|bearer-required` (`src/server.ts:538-541`), and §4b forbids secret values / `Authorization` headers / raw env dumps outright. `NFR-B` + `AC-P4-OPS-B` assert 0 occurrences of a synthetic secret across all four subcommands and the state file, patterned on `scripts/verify-env.ts:314-323`. **But** `doctor` C2 attaches the *actual* `Bearer <AGENT_MEMORY_SECRET>` to an HTTP request sent to whatever listener occupies `R(N)` **before** C3 establishes ownership (`SPEC-P4-OPS.md:62-66`, `RUNBOOK:53-60`) — the value is never *printed*, it is *transmitted to an unverified party*. That is the same confidentiality outcome and it is finding **S-001 (High)**. `status` reads no secret per §4.1, so it cannot transmit one (ambiguity **S-014**).

**(2) Is the backup archive given a documented permission/PII posture?** — **No.** `REQ-08`/`RUN-REQ-06` specify only "verified non-empty" at `<target>.backup-<UTC-timestamp>`; no file mode, no parent-dir mode, no Ley 172-13 declaration (purpose + TTL + deletion procedure) — the exact declaration shape this repo already applies to other stores (`CONTRACT.md:426-466,479-495`). The archive is a full copy of memory data (PII-class content) at rest. **S-002 (High)** → C2.

**(3) Does `stop` re-verify PID cmdline (TOCTOU R-011)?** — **Yes for SIGTERM** (`RUN-REQ-13(a)`, `§4d(b)`: "verify PID cmdline matches our server → SIGTERM"), and the residual is documented, not silently passed. **Gap: the SIGKILL escalation does not re-verify** — after the bounded grace period the PID may have exited and been reused, and the spec'd sequence SIGTERM → wait → SIGKILL signals it anyway. **S-010 (Medium)** → C10. The Helix side is instance-name-scoped (`helix stop <name>`, name from `helix.toml [local.*]`) — correct, but only if the state file's `helixInstance` is re-derived (S-003).

**(4) Does doctor's report-only posture hold (never signals)?** — **Yes for `doctor` without `--migrate --apply --yes`** (`REQ-OPS-RUN-04`: no stop/signal path reachable; `ARCHITECTURE.md:116-119` Data Flow 3). **It does not hold for `doctor --migrate --apply --yes`**, which by spec stops our own slot server (`RUN-REQ-06(b)`) and runs `helix restart <instance>` (`RUN-REQ-07`). Those are scoped to owned targets only — acceptable — but the report-only guarantee must be stated with that carve-out or an implementer/reviewer will read it as absolute. **S-009 (Medium)** → C9.

**(5) Does the state file schema stay secret-free?** — **Yes.** Fields are enumerated and closed: `slot`, `pids{rest,helix}`, `helixInstance`, `dataDir`, `startedAt`, `cliVersion` — "never a secret, never memory content, never PII" (`SPEC-P4-OPS.md:233-238`, `ARCHITECTURE.md:79-84`, INV-004/INV-007), and `AC-P4-OPS-07` asserts no secret in it. Two hardening gaps remain: no file/dir mode (S-012) and no schema validation or field-re-derivation before the fields steer signals (S-003). Content is secret-free; **integrity** of that content is the open issue.

## Conditions for Approval (Verdict: Conditional — 10)

1. **C1 (S-001, High — blocking):** Ownership-gate every authenticated probe. `Authorization` is attached **only after** the listener PID is proven slot-owned (state PID alive **and** cmdline matches our `src/server.ts` launch — the `verifyOwnedPid()` of C3); otherwise send **no** header and FAIL via C3. Extend `AC-OPS-RUN-03` / `AC-P4-OPS-B` with a synthetic-foreign-listener capture asserting zero `authorization` headers received.
2. **C2 (S-002, High — blocking):** Backup archive posture: file `0600`, parent dir `0700` (umask-independent), Ley 172-13 declaration (purpose + TTL + deletion procedure + `~`-collapsed path printing) in the README ops section, `--backup-dir` validated per C4. Evidence: `stat` modes + README anchor in TEST_MATRIX.
3. **C3 (S-003, S-012):** State-file hardening: `state/` `0700`, `slot-N.json` `0600`; closed-schema validation with fail-closed refusal (no signal on unknown/missing/mistyped fields); `helixInstance` re-derived from slot + `helix.toml [local.*]`, mismatch → no signal; state `dataDir` informational only; one shared `verifyOwnedPid()` used by `stop` (pre-SIGTERM, pre-SIGKILL) and by `doctor` C3.
4. **C4 (S-004):** Path validation: `start` refuses a non-empty, non-Helix data dir (never adopts a foreign dir), refuses `/`, `$HOME`, system roots; `--backup-dir` parent must exist + be writable with a fixed archive-name pattern.
5. **C5 (S-005):** `start` idempotence: live, cmdline-verified state → `already running` (exit code declared by R1; default 0), live PIDs never overwritten; stale state cleaned then proceed; proof in `verify-ops` §B.
6. **C6 (S-006):** Governance/audit lines for `stop` and `--migrate --apply` (allowlisted fields only, oneLine, emitted before every non-zero exit including `MIGRATE ABORT`), store = stdout/stderr with the purpose/retention declaration shaped like `CONTRACT.md:479-495`.
7. **C7 (S-007, S-013):** One allowlist renderer for **all** doctor/status/migrate text: child-process output captured and re-rendered (never raw), every error oneLine-collapsed + `$HOME`→`~`, no raw `Error`/env dumps (§4b verbatim as the field contract).
8. **C8 (S-008, S-011):** Env minimization + binary resolution: `AGENT_MEMORY_SECRET` stripped from every child except `npx tsx src/server.ts`; absolute-path resolution of `helix`/`npx` where feasible, else PATH-trust documented as accepted residual in README + this review.
9. **C9 (S-009, S-014):** Runbook §4c declares the migration instance lifecycle (target Helix stopped during copy, started for verify); REQ-OPS-RUN-04 restated as "doctor without `--migrate --apply --yes` is read-only"; the `status`/bearer row reconciled (E-3) with C1's gate applying if a bearer is ever sent.
10. **C10 (S-010):** Re-verify PID cmdline immediately before SIGKILL; mismatch → no signal, allowlisted `stale-pid` note, exit 1 fail-closed (start-time comparison recommended where `/proc` exists).

**Blocking set for `execute-spec`:** C1 and C2 are High — implementation must not start until both are carried into `SPEC-P4-OPS` / `SPEC-P4-OPS-RUNBOOK` (or the proposal) and traceable to evidence rows.
